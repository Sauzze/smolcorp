# Contributing to Smolcorp

Thanks for wanting to help. Smolcorp is built by a small team with a clear direction, so contributions follow a few rules.

## Start with an issue or a discussion

- **Bugs:** open an issue with what you did, what you expected, what happened, and your system (Mac, Windows or Linux, and the Smolcorp version).
- **Ideas and questions:** start a discussion.
- **No pull request without an approved issue.** Wait until the maintainer says yes on the issue before you write code. Pull requests that don't link an approved issue are closed, with a pointer back here.

## Small fixes are welcome straight away

Typos, broken links and wording fixes in the docs can go straight to a pull request.

## Pull requests

- Link the approved issue.
- Keep it small: one change per pull request.
- Say how you tested it, on which system.
- Follow the code and wording already there.
- Don't add new dependencies, telemetry, accounts or network calls without agreeing it on the issue first.
- Never commit keys, tokens, personal paths or `.env` files.

Every pull request is reviewed and merged by the maintainer. Being merged doesn't come with write access to the repository.

## Security

Please don't report security problems in a public issue. Use GitHub's private vulnerability reporting on this repository instead.
